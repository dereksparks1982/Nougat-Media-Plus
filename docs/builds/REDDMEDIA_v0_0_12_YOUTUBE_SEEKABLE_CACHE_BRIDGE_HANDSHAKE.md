- Same-version UI/identity repair: creator-facing `yt-dlp` labels are now **YouTube**; the window title is `★ ReddMedia`; the in-app right label is `v0.0.12`; and the ReddMedia icon identity is a red star.
- Replaced v0.0.11's one-way YouTube stdout-to-libVLC playback handoff with a temporary yt-dlp/FFmpeg cache served through an internal HTTP server.
- The HTTP server binds only to `127.0.0.1` on an ephemeral port.
- YouTube Play keeps the exact default selector `bv*[height<=1080]+ba/b[height<=1080]`.
- ReddMedia probes video duration with the bundled yt-dlp engine before starting playback so the normal seek timeline can address the complete video.

- Seeking inside already-reached cached playback uses the local HTTP source.
- Seeking beyond the current cached playback segment stops the obsolete bridge and restarts yt-dlp from the requested timestamp using `--download-sections` and `--force-keyframes-at-cuts`.
- Replacement playback, Stop, and clean shutdown terminate the feeder/server and delete the temporary cache file.
- Embedded libVLC playback remains inside ReddMedia.
- Version identity advances from `ReddMedia_v11` to `ReddMedia_v12`.

## Known risks

- A seek outside the current cached segment requires a new yt-dlp/FFmpeg segment and therefore may pause briefly while the new location buffers.
- Timestamp cuts are keyframe-aware and can begin near, rather than at the exact millisecond requested by the user.
- Network speed and source availability still control startup and seek-buffer time.
- Container probing behavior varies by source format; target-machine owner testing with the accepted YouTube fixture remains the final playback/seek proof.
