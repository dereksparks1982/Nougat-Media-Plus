# Nougat Play Portal v0.0.67 HVR-955Q FM Final Repair Candidate

This candidate replaces the earlier iterative kernel build attempts with one transactional repair.

What changed from the rejected attempts:

- It derives the exact Ubuntu source package name and version from the installed running-kernel headers using dpkg metadata.
- It fetches that exact Ubuntu source version, with a Launchpad source-archive fallback if APT source indexes no longer carry it.
- It builds external modules against `/lib/modules/$(uname -r)/build`, so the ABI is the running kernel ABI.
- It restores the stock HVR driver before building, removing the previously rejected Nougat override.
- It installs the new modules transactionally. If module loading, DVB preservation, `/dev/radio*`, or a real 100.1 MHz V4L2 tune fails, the script automatically removes the Nougat override and reloads the stock TV driver.
- It saves a diagnostic kernel log automatically on driver failure. No separate diagnostic command is required.
- It does not touch Git or GitHub.

Kernel changes:

- HVR-955Q cx231xx board advertises a V4L2 radio device.
- cx231xx radio open reuses the existing tuner/SIF audio route and cx25840 radio mode.
- cx231xx sends radio mode to the Si2157 analog tuner path.
- cx231xx uses the documented 6.6 MHz HVR-9xx FM IF.
- Si2157 no longer rejects `V4L2_TUNER_RADIO`.
- Si2157 FM uses the existing upstream analog command sequence rather than inventing a parallel register sequence.
- FM supplies the values already left in upstream source comments: 1.7 MHz bandwidth and 6.6 MHz HVR-9xx IF.
- Si2157 RF strength is surfaced through the cx231xx V4L2 radio tuner so native scanning has measured signal data.

Nougat changes:

- Native `/dev/radio*` discovery through `V4l2RadioProvider`.
- HVR WFM receive uses V4L2 tuning and cx231xx ALSA capture, not `rtl_fm`.
- HVR scanning uses native tuning/signal readback, not `rtl_power`.
- RTL-SDR remains available for actual RTL hardware.
- Manual gain is not falsely presented as controlling Si2157; the HVR path reports hardware AGC.
- v66 is removed from the project root only after a successful v67 application build.
- Approved `nougat-play-portal` icon metadata is applied.
- Final executable identity must contain `v0.0.67`.

The candidate still requires Derek's physical acceptance test: intelligible FM audio, station scan quality, hotplug behavior, and TV -> FM -> TV regression.

## ABI-safe correction after repeated cx231xx_dvb load failure

The earlier candidate changed the `cx231xx_set_analog_freq` callback signature and
added a member to the public `struct cx231xx`. Even with matching vermagic, that
needlessly changed the media-driver ABI surface.

This revision removes those public-header changes entirely. `cx231xx.h` is left
untouched. Radio mode is carried through existing driver state, and only the
modules whose implementation actually changes are overridden: `cx231xx`,
`cx231xx_dvb`, and `si2157`. The stock `cx231xx_alsa` module is retained.

The script also reuses the already downloaded exact Ubuntu 7.0.0-30.30 source
when it is present under the Nougat Play Portal project build directory.

## Two-module FM repair

The previous driver candidate still replaced `cx231xx_dvb`; that was the module
the running kernel rejected with `Invalid argument`.

This revision no longer compiles or installs a custom `cx231xx_dvb` or
`cx231xx_alsa`. Ubuntu's stock extension modules remain untouched. The only
kernel modules overridden are:

- `cx231xx.ko` for HVR-955Q radio-node registration, radio startup, and 6.6 MHz IF.
- `si2157.ko` for FM analog tuning.

The exact Ubuntu 7.0.0-30.30 source archive already stored under the Nougat Media
Plus project build directory is re-extracted into a clean source tree before the
patch is applied. This avoids carrying forward the rejected callback/header patch.

The v67 root executable is also assigned the approved
`assets/branding/nougat-play-portal-dock-N.png` file icon.

## FIX2: exact Ubuntu Si2157 source-anchor correction

The prior two-module package stopped before compilation because its Python
patcher expected the Si2157 `color` declaration with spacing that does not match
Ubuntu linux 7.0.0-30.30.

FIX2 uses a spacing-tolerant source match for that declaration and removes the
existing upstream FM rejection block directly. It also removes guessed radio
board mux values and uses the established `AUDIO_INPUT_TUNER_TV` route while
the cx25840 subdevice is switched into radio mode.

## FIX3: scope Si2157 patching to the analog tuning function

FIX2 reached the exact Ubuntu 7.0.0-30.30 source and then stopped because the
generic `if (!dev->active)` block occurs twice in si2157.c. FIX3 scopes all
Si2157 FM edits strictly to `si2157_set_analog_params()`, so the identical
digital-path block is no longer an ambiguous patch target.



## FIX4 strict-unload correction

The prior two-module candidate resolved the custom module files correctly but did not prove that the resident stock `cx231xx` core had actually been removed. The captured kernel log showed `cx231xx_dvb` being removed while the core remained resident, with no fresh HVR core probe and no radio registration. `cx231xx_alsa` was still holding the core.

FIX4 therefore treats module replacement as transactional and observable:

- unloads `cx231xx_dvb`, `si2157`, `cx231xx_alsa`, and `cx231xx` in dependency order,
- if the desktop audio stack is holding the HVR ALSA capture device, temporarily releases PipeWire/WirePlumber and retries,
- refuses to continue unless all four modules are actually absent from `/proc/modules`,
- only then installs and loads the Nougat `cx231xx` and `si2157` overrides,
- automatically restores the desktop audio stack on success or failure,
- retains stock-driver rollback if the candidate fails.

This fixes the false-positive state where `modinfo -n` pointed at the Nougat override while the already-loaded stock core was still servicing the hardware.

## FIX5: reboot-safe installation

Two FIX4 attempts caused the desktop to become completely unresponsive during
live HVR/audio/media module replacement. FIX5 removes that behavior entirely.

FIX5 does not:

- unload or reload `cx231xx`, `cx231xx_alsa`, `cx231xx_dvb`, or `si2157`;
- stop or restart PipeWire or WirePlumber;
- detach the HVR from the running kernel;
- require `/dev/radio0` before the application build.

Instead it builds the two patched modules, installs them under the running
kernel's `updates/nougat-v67-fm` directory, runs `depmod`, builds the v67
application, applies the approved executable icon, and returns to the terminal.

The currently running stock driver remains untouched. A normal reboot is
required before the patched driver can be loaded fresh. Build concurrency is
limited to two jobs at low CPU priority to keep the desktop responsive.
