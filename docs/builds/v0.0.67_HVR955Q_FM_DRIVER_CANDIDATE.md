# Nougat Media Plus v0.0.67 HVR-955Q FM driver candidate

Scope: receive-only FM for Hauppauge WinTV-HVR-955Q (111401 / USB 2040:b123).

This candidate addresses the hardware-side blockers confirmed on saxondesktop:

- cx231xx exposes video/VBI/DVB but no `/dev/radio*` node.
- the HVR-955Q board definition does not advertise a cx231xx radio input.
- the cx231xx radio-open path still contains the historical commented-out startup placeholder.
- Si2157 explicitly rejects `V4L2_TUNER_RADIO`.
- the Si2157 source itself documents 1.7 MHz as the narrowest practical FM bandwidth and 6.6 MHz IF for HVR-9xx/cx231xx.
- Nougat's old RadioBackend falls through to rtl_fm/rtl_power because no native radio node exists.

Candidate changes:

1. Advertise the HVR-955Q cx231xx radio input and register `/dev/radioN`.
2. Report broadcast-FM V4L2 LOW-unit range 87.5-108 MHz.
3. Forward V4L2 radio mode through the cx231xx DVB tuner callback.
4. Configure the cx231xx low-IF path for the documented 6.6 MHz FM IF.
5. Replace the Si2157 FM hard rejection with an HVR-9xx-specific analog FM tune path.
6. Reuse cx25840's existing radio audio configuration on frequency changes.
7. Wire Nougat RadioBackend to the native V4L2 provider for the HVR.
8. Use cx231xx ALSA capture for LISTEN instead of rtl_fm.
9. Make HVR scanning use native V4L2 tuning instead of requiring rtl_power.
10. Rebuild `Nougat_Media_Plus_v67`, remove v66 from the project root, and assign the approved `nougat-media-plus` icon.

No RF transmit code is included.

The installer refuses to call this candidate applied unless the patched kernel stack actually creates `/dev/radio*`. Physical FM audio, scan quality, signal strength, hotplug, and TV->FM->TV still require validation on the actual HVR-955Q.
